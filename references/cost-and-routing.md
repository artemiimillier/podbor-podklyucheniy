# Стоимость нагрузки и распределение между провайдерами

Читайте для регулярной задачи, сравнения тарифов или связки бесплатных квот. Для одного уже доступного локального действия расчёт нескольких подписок не нужен.

## Сначала сравните одинаковый результат

- Запишите нужные операции, объём по каждой, качество и единицу результата. «Запрос» может означать страницу, файл, минуту, результат поиска или пакет записей. Разные единицы нельзя складывать как одинаковые.
- В стоимость успешного результата включайте обязательные шаги: например, поиск + получение полного текста, OCR + извлечение таблиц, распознавание + разделение говорящих. У одной операции могут быть разные множители кредитов.
- Для каждого финалиста сохраните прочитанные официальные страницы функций, цены и квот с датой. Сравните цену API и цену посредника/MCP, если это разные платежи. Одинаковый API через CLI и MCP не создаёт два бесплатных баланса.
- Проверьте повторяющуюся квоту, разовый trial, срок действия кредитов, коммерческое использование, обязательность карты/подписки, ограничение скорости и параллельности. «До N» — верхняя граница, а не гарантированная ёмкость. Недоступная цена остаётся неизвестной.
- Проверьте качество на нужном языке/формате, полноту результата, стабильность авторизации и совместимость с Hermes. Если это подтверждено только документацией, не называйте интеграцию проверенной вызовом.

## Расчёт

Для операции `j` у поставщика `i` запишите объём `n_ij` и расход кредитов на единицу `k_ij`. Нагрузка в кредитах:

`C_i = sum(n_ij * k_ij)`.

Если эти операции делят один баланс `Q_i`, не вычитайте бесплатную квоту заново для каждой операции. Для линейного тарифа с ценой `r_i` за платный кредит:

`E_i = max(0, C_i - Q_i)`;
`API_i = E_i * r_i`.

Эта формула подходит только когда бесплатная квота применима к выбранным операциям и опубликован линейный тариф превышения. Для пакетной продажи кредитов округлите число необходимых пакетов вверх. Для ступенчатого тарифа, минимального платежа или обязательного плана рассчитайте реальные условия поставщика вместо линейной формулы. Не вычитайте разовый trial из каждого будущего месяца.

Полная месячная стоимость: необходимые планы + потребление + отдельная плата за посредников + модель + сервер/вычисления + сопровождение. Не считайте дважды включённые в подписку кредиты. Первичную настройку показывайте отдельно. Укажите стоимость всей известной нагрузки и стоимость успешной единицы результата; неизвестные слагаемые не равны нулю. Считайте инструментом, валюты не смешивайте без явного курса и даты.

## Когда несколько провайдеров полезны

Предлагайте комбинацию только если функции и качество совместимы, использование соответствует условиям каждого поставщика, а экономия или надёжность оправдывает дополнительную настройку. Нужны разные разрешённые балансы, а не повторное использование одной квоты через разные интерфейсы. Не создавайте аккаунты ради обхода лимитов.

Для одной эквивалентной операции с бесплатной квотой `Q_i` кредитов и расходом `k_i` потенциальная ёмкость поставщика — `floor(Q_i / k_i)` единиц. Суммировать её можно лишь для одного периода, совместимого результата и нагрузки, которую можно распределить. Дневные квоты нельзя безусловно умножить на месяц: учитывайте календарь поступления задач и допустимость очереди. При нескольких операциях используйте общий баланс `C_i`, а не сумму независимых максимумов.

В рекомендации укажите:

1. Как распределяются операции/объём между поставщиками и какие функции остаются только у основного.
2. Сколько применимых бесплатных единиц доступно, в какие даты обновляются квоты, где разовый trial.
3. Платный остаток, его тариф и итоговую стоимость; неизвестное превышение — повод остановиться перед расходами.
4. Правило выбора: подходящие функции/качество → доступный лимит скорости и остаток → цена успешного результата. Резерв используется при явном лимите или подтверждённой недоступности; ошибка качества не исправляется слепым переключением.
5. Единый формат результата, дедупликацию, ограниченные повторы, журнал расхода и бюджет. При тайм-ауте платного запроса списание может быть неизвестно: не считать повтор бесплатным. После исчерпания разрешённого бюджета — очередь/остановка, а не автоматический платёж.

Маршрутизация здесь — проект решения, а не готовый технический маршрутизатор. Если существующий клиент не поддерживает остатки и переключение, отметьте необходимость скрипта/оркестратора и стоимость его настройки. Не утверждайте, что MCP самостоятельно распределит запросы.

## Условный пример арифметики

Это вымышленные данные для проверки расчёта, не цены существующих сервисов. Нагрузка — 2 500 эквивалентных операций в месяц. Провайдер A даёт 1 000 ежемесячных бесплатных кредитов, операция стоит 1 кредит, платное превышение — $0.01 за кредит. Провайдер B даёт 800 ежемесячных кредитов, операция стоит 2 кредита; бесплатный API разрешает нужную функцию. Другие ограничения и расходы в примере не заданы.

Распределение: 1 000 бесплатных операций A + 400 бесплатных операций B + 1 100 платных операций A. Прямые API-расходы — $11. Один A обошёлся бы в $15. Экономия прямого потребления — $4 в месяц; дополнительные настройка, модель и вычисления не включены и могут превысить её. Значит, «два бесплатных тарифа» не делают задачу полностью бесплатной и не гарантируют, что связка выгоднее одного A.
